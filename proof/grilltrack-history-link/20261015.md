# Explicit committed historical witness

A retained historical join can have genuine committed canonical ledger/events
without being the current track or a closed archive. `history-link` records that
provenance without changing its paused lifecycle or decisions, or current state.
The witness must precede an exact anchor in the same Git ancestry; its canonical
join, event prefix and source closure are recomputed. Only that validated closure
can seed roots at the anchor and descendants. A future reconciliation binds
committed link records into its exact plan; ambient files do not qualify.

Neutral regression: CLI-produced V1/V2 joins, with a genuine paused later join
and a subsequent canonical continuation of the earlier track. Before the new
operation, unwitnessed reconciliation rejects the retained later root. Explicit
preview/apply followed by committing the additive record permits planning;
canonical files and historical pause/decision bodies remain byte-identical.

The implementation has no product credentials, Store data, imported decision
bodies or hosted mutations. `history-link` defaults to preview and requires an
exact target-bound plan digest for additive apply. Apply changes only one link
record, never canonical ledger/events, existing lineage objects or archives.
Documentation defines input/output, failure and retry behavior. Relevant tests
cover stale approvals, forged/missing provenance, ancestry, immutable records,
uncommitted ambient records and inherited-link deletion. Existing nested/retention
negative suites remain required. Runtime results and final source/review receipts
are maintained in the task's local run proof, not asserted by this source note.

No merge or global installation is authorized by this patch. Consumers must
review/adopt an exact tooling revision locally before any real history apply.
