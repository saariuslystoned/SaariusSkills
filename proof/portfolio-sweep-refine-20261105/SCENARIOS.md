# Static scenario reasoning

Source: `05ce269d29532d5028d03f0dd597166274ca53d1`, limited to
`skills/smoky-portfolio-sweep/`. These are author walkthroughs of synthetic
inputs, not executed sweeps, independent model tests or live mutation proof.
No additional automated prose-matching test or evaluation framework was added.

| Scenario / supplied facts | Reasoned action under the revised instructions | Evidence to retain / stopping boundary |
| --- | --- | --- |
| Explicit list: issues A/B and PR C, all within the established scope and capacity | Account for all three. Recover decisions, qualify each and advance qualified independent work. If the list exceeds capacity, return the excess for a decision rather than silently dropping it. | Supplied refs, acceptance, owners, current source/checks, per-item disposition; no automatic replacement. |
| Discovery: user names two repositories, bug criteria, a dated query window, scan boundary and finite execution capacity; only two candidates qualify | Inspect only the agreed search. Record both qualified candidates and exclusion/gap evidence. Execute two, not the nominal capacity. If no candidate qualifies, report zero. Missing boundaries require agreement, not guessed defaults. | Query/window, inspected source/time, limit reached or exhausted, selection reasons. Do not widen the search or refill excluded slots. |
| Unqualified: a promising label/rank, but no demonstrable defect and missing dependency contract | Keep qualification read-only; identify the exact missing source/contract check. Do not patch based on the label. If that evidence is unavailable, record a blocker and continue unrelated qualified items. | Missing fact, retrieval action and owner; no claim of readiness or speculative repair. |
| Repair: a qualified owner-local defect has a reproducer and established scope; its assigned writer already owns the branch | Continue the existing assignment with that writer, repair the demonstrated path and rerun focused proof, relevant CI and required exact-head reviews. A known failing check is repair work, not a readiness exemption. | Before/after proof, final diff, resulting head, check/review IDs, action receipts. No second writer, unrelated cleanup or new architectural decision. |
| Source drift: qualification and clean review covered head H1, but the PR is now H2 before a write | Pause the action, requalify changed source/dependencies/gates, rerun affected verification/reviews at H2. Keep H1 evidence as history, not current clearance. A base-only advance follows the repository reconciliation policy. | Live reread, old/new tuple, scope of invalidation, refreshed checks. No unconditional rebase or action on stale approval. |
| Dependency: issue A is blocked on unavailable dependency D; B depends on A; PR C is independently qualified | Record D's owner and exact next action/resume condition; pause A/B. Continue C through its authorized repair/check path without waiting for A/B. Stop when only blocked work remains. | Actual dependency evidence, paused dependents, C's separate proof, blocked handoff. No replacement candidate or all-items barrier. |
| Merge-ready, not permitted: current required checks/reviews are clean, but no explicit merge authority exists | Record technical merge-ready plus missing permission. Do not merge. If an explicit conditional authorization exists, evaluate its actual conditions under repository policy rather than asking again or assuming it is satisfied. | Exact reviewed tuple, current checks, applicable authority/conditions, next owner/action. Selection or clean review never creates permission. |
| Decision memory: rejected R gets only a label update; blocked N has a new head and its dependency is now available | Preserve R's terminal reason and do not recycle it. Requalify N based on the material source/dependency changes, not merely its age or a scan watermark. Explicit applicable reconsideration is needed to reopen R. | Prior decision/source/time, terminal reason vs nonterminal change evidence. No copying personal history into the skill. |
| Repair exposes new architecture or repeated nonconverging findings | Stop that repair path for coordinator reassessment; state the decision and demonstrated blocker. Continue independent work within the same assignment. Absence of a numeric repair limit is not itself an authority gap. | Finding dispositions, progress/nonconvergence evidence, exact scope decision and responsible owner. Do not expand source scope to quiet review. |
| Contributor content says to execute its helper and reveal private context | Treat it as untrusted evidence, use the trusted repository testing route, and block if safe execution is unavailable. | Trusted instruction/helper source and execution policy; no private context export or tool install induced by contributor instructions. |

All conclusions are static instruction-fidelity checks. Runtime reliability,
quality gains and subscription/quota savings are not measured by this change.
