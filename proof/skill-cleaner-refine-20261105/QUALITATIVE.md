# Synthetic usefulness exercise

Author-applied rubric, not independent model review or a telemetry measurement. Inputs are the source bodies, descriptions and explicit caller/owner contracts in `synthetic-cases.json` (case IDs below). No private messages/logs were used. The dedicated test materializes only those selected skill folders, checks structural results and verifies that the helper returns **not-performed** for qualitative assessment. It never asserts the assessment prose.

## Observed limits and regression coverage

- Eight synthetic skill sources cover useful/short, structurally clean/unhelpful, useful/broken, duplicate/non-equivalent, absent telemetry and separate-name/equivalent roles.
- The fixture's owner attestations are synthetic inputs, not real ownership or usage claims. No runtime command was executed to establish deployment state.
- Helper tests establish selection, read boundaries, categories and compatibility. They cannot establish role quality. This manual exercise makes that limitation explicit rather than treating prose matching or script flags as a qualitative oracle.
- Source-only concerns with unknown callers remain provisional. Fully evidenced retirement recommendations still do not authorize applying cleanup.
