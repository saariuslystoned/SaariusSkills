# Smoky Coordinator

Use this public core for one enduring parent conversation that owns project
decisions, evidence, acceptance, and the next action. Read repository
instructions and available skill metadata first. If either identifies a
configured private operator or repository profile, including an optional binding
or an installed profile-specific variant of this skill, read and honor that
binding before applying this core. The public core must not bypass or
replace a configured private binding; it supplies local targets and policy but
does not grant authority. Keep the workflow capable-host independent: it must
work generically on Codex, Claude Code, Cursor, AGY, or another supported host
without inventing worker lanes. Do not invent a scheduler, queue, status store,
or private model roster.

## Admit and route

Record the objective, owner, exact source, scope and exclusions, acceptance,
dependencies, proof pointers, stop condition, and next action in the existing
task record. Preserve the original objective when an owner asks for status or
an aside; make a scope decision before admitting a tangent. Keep sibling lanes
as a compact status-only roster and do not touch their files.

Prefer ACP for substantial implementation, research, diagnosis, and suitable
proof when a qualified lane is available. Follow
[`acp-delegation`](../acp-delegation/SKILL.md) for readiness, model selection,
permission, and result handling; do not duplicate its adapter contracts.
Select by explicit instruction, task fit and proven quality, known headroom or
reset, and existing preference. Unknown usage is not a blocker or a basis for
invented savings. If no suitable lane is ready, use authorized native tools and
record the fallback. Never bypass a human gate, provider restriction, or
uncertain active writer.

Give each worker a grounded, compact handoff containing the task, target and
revision, allowed actions, acceptance and proof, writable owner, relevant
skills, next gate, and stop condition. Require an acknowledgement. Use one
owner/worktree per conflicting target. Keep full logs and artifacts outside
the coordinator context; inspect only what acceptance needs. Process ready
outcomes independently rather than waiting for an all-workers barrier.

## Recover and accept

Routine authorized recovery, including diagnosis and repair of a technical
failure within existing authority, is autonomous; do not turn that failure
into a human question. Surface `WAITING_FOR_HUMAN` only for a genuine new
authority, scope, product, or approval gate, with the exact decision and
preserve ownership. Never evade a gate by duplicating or reassigning work.
Before replacement, prove termination and cleanup, inspect partial work, and
explicitly transfer ownership. Reuse standing authority instead of
manufacturing new gates.

Independently inspect the output, changed source, acceptance, and proof.
Record accepted or rejected outcomes, rework, owner interventions, and
supported measurements for later refinement. Keep repository review policy
authoritative and never self-merge. Existing Harness² routing remains
available for a reproducible workflow weakness with measurable acceptance; it
is not a runtime prerequisite. Skill reads and activity are not quality or
savings evidence, and do not trigger automatic skill edits.

At handoff or compaction persist decisions, active job/target/owner, exact
source, proof pointers, and next action in the existing task record. Preserve
the original objective and report one clear next gate.
