# Puppet v0.2 fast-launch slice

Status: implementation candidate; deterministic verification complete, live
subscription-backed forward proof pending an immutable committed head.

## Operator outcome

An operator may explicitly select any one-to-five-target mix from AGY, Codex,
Claude, Cursor, and Grok. A supervising agent prepares one exact ordinary-run
plan per selected target and submits the set once. Puppet concurrently:

- verifies every plan, controller, artifact, warm qualification blocker set,
  worktree, run root, profile root, campaign, and command vector;
- recompiles all plans behind a global read-only barrier before starting any
  harness;
- launches only the selected exact v0.1 controllers in isolated child sessions;
- emits immediate target-labeled progress instead of remaining silent;
- preserves active siblings when a post-barrier lane fails;
- reconciles every failed submitted launch with exact read-only status;
- refreshes attach tickets or opens native read-only TUI views only after all
  launches settle;
- supports concurrent status, attach, view, and exact halt for the same plan
  set; and
- binds the result to every plan hash, the plan-set hash, the fanout script,
  adapter, protocol, and v0.1 controller identities.

## Safety boundary

The coordinator is additive and remains outside the v0.1 adapter implementation
fingerprint. It cannot probe, qualify, onboard, log in, route targets
automatically, add native slash commands, or halt a successful sibling.
Existing single-lane controllers retain auth, source, process, tmux, delivery,
checkpoint, and exact-halt authority.

Each controller child has a 120-second deadline. On expiry, the coordinator
sends SIGINT only to that exact child and waits 15 seconds for controller cleanup.
It then uses bounded TERM/KILL fallback only on that lane's isolated owned process
group and reports `recovery_required`. Operator Ctrl-C sets a shared cancellation
event; every exact child gets a shorter five-second cleanup window before the
same owned-group fallback, so executor shutdown is bounded by cleanup rather
than the 120-second controller deadline. Children are placed in separate
sessions so terminal signals are never broadcast to unrelated processes.
Queued children do not start after cancellation, and repeated Ctrl-C is
idempotent while the recovery receipt is assembled.
Child pipes are drained continuously with a 1 MiB in-memory cap per stream.
Aggregate results contain only action-specific projected fields and stable
error categories, never raw controller objects or arbitrary error/detail text.
Pipe-holding descendants cannot pin cleanup, including descendants outside the
owned process group; their output fails closed without cross-thread pipe close.

## Verified here

- Five launch callbacks overlap behind a deterministic barrier.
- A runtime failure remains lane-local and never invokes halt.
- Invalid roots include the full cross-lane worktree/run/profile product.
- Proof and state roots remain exactly `run/proof` and `run/state`.
- Canonical `--json` controller argv and macOS lexical paths round-trip through
  one genuinely compiled operator-plan v1 packet.
- Source-only, target-gated, stale, or otherwise extra-blocked plans are not
  admitted as warm launches.
- Attach/view failures are visible separately from launch success.
- Failed submitted launches receive exact status reconciliation and recovery
  commands.
- Uncertain halts receive the same read-only reconciliation without automatic
  retry.
- Initial launch attach commands are omitted after a slow batch; the refreshed
  `viewer.result` is canonical.
- Attach supervision is bounded to 13.25 seconds end to end, below the
  controller's 30-second ticket TTL, so a stalled sibling cannot make a
  reported attach command stale.
- Validated launch-incomplete blocker metadata identifies the narrow Grok
  dead-lease candidate without retaining cleanup error text.
- Forbidden body-shaped child JSON is rejected; unrecognized successful fields
  and arbitrary failure error/detail text are never re-emitted.
- Oversized child streams are continuously drained, bounded in memory, and
  rejected without a disk-growth or pipe-backpressure failure mode.
- Ctrl-C actively cancels exact isolated controller children and emits a
  structured recovery receipt after bounded cleanup.
- Lifecycle fanout targets only the selected exact state-root/session pairs.
- The fanout script does not change adapter, protocol, or target instruction
  qualification fingerprints.
- Plugin metadata advances from 0.1.0 to 0.2.0.
